# MAX Bot

Локальная основа бота для уведомлений о кандидатах, направленных на объекты.

Сейчас проект работает только с вымышленными данными. Он не подключается к
Битрикс24, MAX или Timeweb и не отправляет настоящие сообщения.

## Что уже реализовано

- безопасные настройки без токенов;
- модель события направления;
- проверка обязательных полей;
- подтверждённый шаблон обычного сообщения;
- предварительный шаблон сообщения об ошибке;
- тестовый журнал SQLite;
- защита от дублей по паре «ID сделки + время входа в стадию»;
- локальные автоматические тесты.
- подготовлена личная доставка ответственному за объект: компания →
  `ASSIGNED_BY_ID` → защищённая локальная связь Bitrix ID с MAX user_id;
- групповая и личная отправки учитываются в журнале раздельно, поэтому ошибка
  личной доставки не повторяет сообщение в общей группе.
- при запуске бот выдаёт сотруднику постоянный шестизначный код привязки;
  по коду можно однозначно связать регистрацию MAX с профилем Битрикс24 даже
  при одновременной регистрации нескольких сотрудников.
- основной менеджер объекта берётся из `ASSIGNED_BY_ID`, дополнительные — из
  настраиваемого множественного поля компании; каждый уникальный менеджер
  получает одно личное сообщение.

Запуск происходит при каждом входе сделки в стадию
`Направлен на объект` (`STAGE_ID=3`). Конкретный переход определяется по
стандартному служебному полю `MOVED_TIME`. Изменения полей внутри этой стадии
повторную отправку не вызывают.

Название кандидата берётся из `TITLE` сделки. Полное ФИО, дата рождения и телефон
берутся из связанного контакта: `LAST_NAME`, `NAME`, `SECOND_NAME`, `BIRTHDATE`
и `PHONE`. Значение телефона не переформатируется.

## Подтверждённая структура CRM

- воронка `Вахта`, ID `0`;
- стадия `Назначено собеседование`, код `NEW`;
- объект связан с компанией, его название берётся из `TITLE` компании.

Модуль `bitrix.py` поддерживает только чтение и может быть ограничен явным
списком разрешённых ID сделок.

Личная доставка включается настройкой `MAX_PRIVATE_DELIVERY_ENABLED` только
после тестовой привязки сотрудника. До этого рабочая групповая рассылка
действует без изменений. Дополнительный доступ Битрикс24 к сотрудникам не нужен.
Код поля компании с дополнительными менеджерами задаётся в
`BITRIX_ADDITIONAL_OBJECT_MANAGERS_FIELD`.

Для мгновенного запуска выбрано событие `ONCRMDEALUPDATE`. Локальный обработчик
проверяет тип события, защитный токен, домен портала и числовой ID сделки.
Регистрация обработчика в Битрикс24 пока не выполнялась.

Позднее выбран более простой рабочий вариант без исходящего вебхука:
периодический опрос новых входов в стадию через `crm.deal.list`. Плановый
интервал — 10 секунд. Запрос выбирает только ID, `MOVED_TIME`, воронку и стадию;
остальные данные читаются только после обнаружения нового входа в нужную стадию.

Серверный обработчик доступен по маршрутам:

- `GET /health` — безопасная проверка работы;
- `POST /bitrix/event` — приём события Битрикс24.

Gunicorn слушает только локальный адрес `127.0.0.1:8765`, а внешний HTTPS
предоставляет реверсивный прокси FastPanel.

## Как запустить тесты

Из папки проекта:

```powershell
python -m unittest discover -s tests -t . -v
```

Для тестов не нужны установка пакетов, доступ в интернет или настоящие ключи.

## Важные ограничения

Неизвестные внутренние коды полей Битрикс24 не придуманы. Реальные подключения,
отправка сообщений и размещение на сервере будут добавляться только после
отдельного разрешения.
